# TSL 阶梯算例与五小时比较协议

本批只准备算例、冻结程序和运行脚本。生成、预检、查看状态、整理报告均不会调用优化器；只有明确的 `run` 子命令启动实验。

## 算例

以 `examples/tsl_2l20h50od` 为基准，生成 nL / 10nH / 25nOD，n=1,…,10。L 为候选基地，H 为候选柜点，OD 为真实订单的聚合需求类型；K 是单次任务最多配送的订单数。

所有切片使用相同局部坐标中心 (−0.75, 3.25) km。基准面积 33.333333 km²，每平方公里 0.6 个 H；第 n 档面积为 50n/3 km²，正方形边长为 √(50n/3) km。经纬度不能从这个局部坐标直接推断。

| L | H | OD | 切片面积 km² | 边长 km |
|---:|---:|---:|---:|---:|
| 1 | 10 | 25 | 16.667 | 4.082 |
| 2 | 20 | 50 | 33.333 | 5.774 |
| 3 | 30 | 75 | 50.000 | 7.071 |
| 4 | 40 | 100 | 66.667 | 8.165 |
| 5 | 50 | 125 | 83.333 | 9.129 |
| 6 | 60 | 150 | 100.000 | 10.000 |
| 7 | 70 | 175 | 116.667 | 10.801 |
| 8 | 80 | 200 | 133.333 | 11.547 |
| 9 | 90 | 225 | 150.000 | 12.247 |
| 10 | 100 | 250 | 166.667 | 12.910 |

使用与基准相同的美团 TSL 原始文件及 SHA-256、2022-10-17 至 2022-10-24、每日 12–13 时需求、08–24 时候选点窗口。取送两端均须在切片内。保留全部符合条件的实际订单，聚合为 25n 个 OD；不按面积放大需求、不生成虚构订单。各档有效需求暴露时间均为 8 小时。除 n=2 逐文件复制基准外，其余档按相同种子和方法独立聚类；地图切片嵌套，候选点集合不要求嵌套。

物理、成本、折旧、柜容量、任务时间上限、需求构造方法均继承当前基准。每档只有一份 `consecutive-csv/1` 输入，K1/K2 只覆盖 `max_orders`，不会重新校准需求或更改 κ。原始数据和论文不修改。

直接飞行网络的 κ 使用精确存在性检查：固定第一单交付柜点，分别求满足各自交付时限的最小前半程、最小后半程操作时间，再检查总任务上限。正值必须有权威资源构造器验证的完整任务见证；数值边界回退穷举。这里不需要保存所有可行路径。非直接/显式路线网络仍按原路径域完整枚举。`complete_double_paths=null` 表示没有计算路径总数，不表示没有路径。

## 实验协议

10 档 × K1/K2 × 3 种方法，共 60 组：

- `full_cplex`：C++ / CPLEX 完整路径模型。
- `benders_cplex`：当前 C++ / CPLEX Benders + 标号定价 CG；保持精简主问题、容量割与 CG/Benders 割同候选生成、根节点三轮 CG，以及当前其他加速策略。
- `full_gurobi`：Python / Gurobi 完整路径模型。

每组 18,000 秒，求解器 1 线程，同时最多 3 组。BLAS/OpenMP 等线程环境也设为 1。按 L、K、方法排序滚动派发；先完成的任务释放并发槽位。没有跨方法热启动或外部固定设计。种子 43，目标相对 gap 为 0，允许求解完成后提前结束。

统一的 5 小时预算包括读取、完整枚举或隐式支持准备、模型构造、优化；最终写出和独立验证另外记录。保留求解器实际优化时间、全部阶段耗时和进程墙钟时间，避免混淆。进程超过预算及 600 秒收尾宽限后由 watchdog 终止，并按异常状态记录，不能标为正常完成。

两个完整模型都显式取消路径数/变量数人为上限。不能完成完整枚举或建模时，如实记录所在阶段、已生成数量和终止原因，不能将截断模型称为完整模型结果。算法的每轮 512 列为插入批量设置，不是全路径数量上限；只有完整定价证书才能支持有效 Benders 割。

## 产物与验收

实验目录：`outputs/tsl_scale_ladder/`。

```text
tsl_scale_ladder/
├── instances/L01…L10/           # 标准 CSV、系数、模型、元数据、哈希
├── provenance/L01…L10/          # 原始订单归属、校准结果、生成审计
├── preparation_manifest.json   # 切片、样本数、需求率、代码/原始文件来源
├── experiment_manifest.json    # 不变协议、60 组命令、输入/源码/二进制哈希
├── preflight.json              # 不求解的预检证据
├── frozen/                     # 独立源码快照、协议及 C++ 可执行文件
├── run.py                      # 导入冻结程序；不带参数只查看状态
├── state.json                  # 任务状态与每次尝试的目录
├── runs/Lnn/method/Kk/attempts/001/
│   ├── job.json, execution.json
│   ├── stdout.log, stderr.log
│   ├── progress.jsonl, progress.json
│   ├── resources.csv, resource_usage.json
│   ├── checkpoint.json
│   ├── input_reference.json
│   ├── result.json, solution.json, path_flows.json
│   ├── native_validation.json, artifact_audit.json
│   └── operations/             # 完整运营 JSON、CSV、指标字典及解释
└── analysis/                   # 60 组汇总、阶段表、点表、地图、收敛曲线
```

每组至少收集：目标与成本分解、全局 UB/LB/gap、终止原因、服务量、基地/柜点配置、OD 分配、节点/弧/路径流量、ρ、忙碌时间分解、无人机数、需求及流量守恒、容量残差；以及模型规模、路径/列数、迭代数、定价完成性、各类割数量及原始割/迭代记录。主问题、RMP primal/dual、标号定价、Pareto、启发式、容量割、枚举、建模和写出时间分开保留。嵌套用时与监测 I/O 不重复累加。

资源采样受系统权限限制时明确标记缺失；正常退出使用 `wait4` 保存实际子进程 CPU 时间及峰值 RSS，不以采样缺失冒充零内存。逐阶段全局上下界与局部求解器信息带作用域，RMP/受限模型目标值不会混作全局界。

完成后重新构造实际路径资源并验证全局可行性，对原始解、输入和全部运营表计算哈希。文件缺失、校验失败、未完成全模型构造等状态不会被误标成功。报告包含全部 60 行，未运行和失败明确显示；经过独立认证的中断恢复解可显示可行 UB，但标记 partial/fallback，不能声称正常求解结束。未认证下界留空。

## 操作命令

本次已准备的批次只需使用冻结入口。以下前两条永不求解：

```bash
python outputs/tsl_scale_ladder/run.py status
python outputs/tsl_scale_ladder/run.py preflight
```

之后明确决定开始时执行（本次不执行）：

```bash
python outputs/tsl_scale_ladder/run.py run
```

同一批次再次 `run` 只继续 pending 任务，不覆盖已完成结果。进程锁阻止双调度器；发现仍活着的旧进程时拒绝重复启动。中断后先核验已落盘结果；有效完成产物直接恢复 completed。失败任务不自动反复重试。需要重新跑失败项时：

```bash
python outputs/tsl_scale_ladder/run.py run --retry-failed
```

重试写 `attempts/002` 等新目录，保留旧结果，每次重试重新获得完整 5 小时预算。恢复时可从引用式或内嵌式 checkpoint 找回已验证的可行解，写独立 `recovered/`，原始失败产物保留。

独立重建汇总和图表不求解：

```bash
python outputs/tsl_scale_ladder/run.py report
```

从零准备另一批次时，先生成新目录、编译，再冻结；所有目标拒绝覆盖：

```bash
python -m src.data.scale_ladder --output outputs/NEW_BATCH
make -C cpp -j2 all
python -m src.experiments.scale_ladder prepare --batch outputs/NEW_BATCH
```

准备阶段只做数据校验、编译和无求解的模拟测试，不验证新的优化结果，也不打开优化器环境检查许可证。
