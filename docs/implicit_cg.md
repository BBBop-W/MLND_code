# C++ 隐式路径列生成

本页对应 C++ / CPLEX 的 `benders_cg`。Python 的目录扫描实现和 C++ 的 `full_path`、`benders_full` 保留为对照。当前任务路径域是直接飞行、一次最多两单；外层是 Benders，内层是 SOCP 列生成，并非整个整数问题的 branch-price-and-cut。

## 1. 子问题为什么总可行

设计向量 d 包括设施、柜子容量档、OD 到有序基地对的分配和航段启用。固定一个满足设计约束的 d，运营子问题 Q(d) 决定路径流量、直接配送量、基地可用概率 rho、空闲无人机和总机队。

将所有订单交给直接配送，令 rho、路径流、首段流、续单量、空闲无人机和机队均为零，就满足当前运营约束。已分配订单不要求实际无人机服务率为正。锥的辅助变量按原模型定义取值，不能把所有辅助变量一概设为零。代码通过公共矩阵检查该基线，而不是仅凭假设跳过可行性核验。

因此初始受限主问题 RMP 可以没有路径列，不需要人工路径、人工罚项或 Phase I。这里的 RMP 指固定设计的连续运营 SOCP，不是外层的整数选址主问题。若将来加入最低无人机服务率等要求，需要重新检查这项性质。

## 2. 贪心初始化生成什么

贪心生成少量路径列及其物理系数，不预先指定选址，也不固定路径流量。列即使加入 RMP，也可以最终取零。

基础贪心对每个“出发基地、返回基地、首单 OD”组合，按路径运营成本与忙碌无人机成本选择少量便宜首段。当前每组最多保留一个首段；能合法返回时加入其单订单路径。K=2 时，仅对这些首段尝试续接第二单，选择节约“两个订单的直接配送成本 − 任务运营成本 − 忙碌机队成本”最多的合法双订单路径。允许 AA。直接基地间空调位路径也作为少量种子。 默认再用 `branch_covering_seed_paths` 补齐必需单单/续单分支；aggregate 组可使用不同首段，prefix 组选择同一首段的完整分支包。覆盖统计、预算与初始设计启发式见 [主问题加强](master_strengthening.md)。这里只是初始列排序，不含精确空闲机队、固定设施和柜格机会成本，也不声称得到最优初始设计。

种子不必覆盖所有任务组合：没有被种子支持的无人机服务可以暂时为零，全直接配送仍可行。之后定价可生成任何合法首段和续单组合，完全不受贪心选取范围限制。跨子问题可以复用已生成列，但必须重新求解、重新定价，不能复用旧对偶证书。

这一组织方式参考 Dayarian 等的作者报告 §5.2：以基本路线初始化，再以可行的 savings 贪心合并扩充列；§5.3 要求启发式之后执行精确定价以认证下界。这里采用的是适合两单任务的简化规则，不称为对原 Clarke–Wright 算法的完整复现。[CIRRELT-2013-57 全文](https://www.cirrelt.ca/documentstravail/cirrelt-2013-57.pdf)

## 3. 预处理与动态列池

预处理读取标准实例，建立物理航段数据、合法首段和任务分支的行索引。首段只描述“基地 → 第一单取件柜 → 第一单交付柜”，不是完整服务路径目录。保留这部分索引，是因为需求递推和首段流量关联需要稳定的公共约束行。

`prepare_path_support` 不生成单订单完整路径、双订单完整路径或空调位路径。输入中已确定的 kappa 原样读取，不根据当前列池重新判断。理论上的所有合法路径由输入数据和资源规则隐式定义。

标号算法从输入网络扩展部分路径，检查任务时间、订单时限、兼容系数和资源系数。完整候选路径的约化成本按公共约束的稀疏列计算；只登记本轮选中的有限批负列。语义相同的路径去重，ID 按登记顺序稳定追加。没有预枚举目录的 ID 查找，也没有为未生成路径分配流量或上界对偶数组。

搜索中仍会临时计算候选路径和后续完成：这属于精确定价。候选负列堆受批量上限限制，支配比较使用有界的后续完成缓存；不持久保存全部完整路径。部分路径标号数仍可能很大，动态列池本身不保证每个实例都提速。

## 4. 一轮规范 CG

1. 最优求解当前 RMP，检查原始可行性。
2. 求出与公共 SOCP 对应的可行对偶，检查修正后的原始—对偶间隙。
3. 对所有有序基地对、单订单、双订单及空调位任务执行精确标号定价。约化成本包括订单、任务分支、柜格占用、机队忙碌、基地平衡和航段约束的对偶价格。
4. 有低于负容差的遗漏列时，登记并加入一批，然后回到第 1 步。批量上限控制加列数量，不限制可搜索的路径域。
5. 只有所有定价块均完成、没有低于负定价容差的遗漏列，且加入微小约化成本误差修正后的完整问题对偶间隙也合格，才能认证 Q(d) 并生成普通 Benders 割。

令 D 为总订单率。每条服务任务至少交付一单，故所有服务路径流之和不超过 D；每个空调位变量也有统一上界 D。若完整定价的最小遗漏约化成本在零附近略负，可用这些界下移对偶目标，得到保守证书。这个修正需要完整精确定价，不能用于将超时或未搜索完成的结果变成证书。

数值不可靠、对偶间隙不合格、定价超时或总体预算用尽时，保留已核验的可行解和此前有效下界，不产生新的未认证割。受限问题的最优费用是完整运营问题的可行上界，不能用作完整问题下界。

RMP 的求解器状态为 Optimal 也必须检查实际残差。若失败，在剩余预算内重新构造同一模型，尝试更严格精度、数值强调、不同缩放和关闭预处理；每次记录于 `primal_attempts`，最终仍使用原有容差核验。对偶也有独立数值恢复和保守修正。恢复不改变数学模型、不放宽验收条件，失败时仍不出割。

Pareto 辅助对偶也使用同一个隐式标号 oracle，逐批分离遗漏列的平稳性约束。被分离列的上界乘子计入辅助目标及最优面条件；未生成列的对应乘子为零。辅助阶段必须独立完成定价和锚点/核心点核验，否则回退到已认证普通割。

## 5. 公共矩阵和全局割

固定设计只改变设计固定行的右端；其余非路径约束、变量界和列系数定义均与当前选址和生成列集合无关。这是把固定设计对偶解释成对所有合法设计有效的 Benders 割的基础。

原目录最紧航段界不适用于动态列池：当前列中没有某条路径，并不表示该路径永远不出现。C++ 改用按任务结构和总需求推导的保守航段界，并由完整模型和 CG 共用。整数航段关闭时禁止流量；开启时界必须覆盖所有合法路径。该替换可能改变分数设计的连续松弛，但不改变固定合法二元设计的运营可行域。测试单独核查这些系数，其他模型系数继续与 Python 对照。

具体地，D 为总订单率、L 为基地数、K 为任务最大订单数。允许的“基地 → 柜子”或“柜子 → 基地”弧上界为 D；“柜子 → 柜子”为 KD；“基地 → 基地”为 (L−1)D；不允许弧及自环为零。服务任务仅在出发/返回接触基地；2K−1 条内部腿中，同一非自环有向弧不可能相邻重复，因此最多出现 K 次。空调位为直接基地间弧，每个变量本身不超过 D，所用 (L−1)D 是保守界。

同理，不能把“已生成路径中的最低成本”冒充所有路径的最低成本。隐式模式现采用输入数据直接推导的单位成本割、解析柜容量收益割和少量运营变量松弛，均不依赖已生成列极值。根节点也可生成经完整定价认证的普通割。具体有效性证明及开关见 [主问题加强](master_strengthening.md)。

## 6. 状态与输出

- `support_complete`：首段/分支等公共模型支持构造完成。
- `catalogue_complete`：是否物化了全部完整路径。隐式 CG 为 false；这不妨碍精确定价。
- `pricing_complete`：对应子问题的全路径域定价与对偶证书通过；不表示外层整数问题达到最优。
- `path_storage=generated_columns_only`：路径记录只含生成过的列。
- `cg_trace`：每轮 RMP、对偶、加列、最小约化成本和认证状态。

`solution.json` 的路径流数组与 `path_flows.json` 的登记列一一对应；较早保存的 incumbent 遇到后续列池扩张时，仅为新列补零。`path_flows.csv` 输出非零流路径。ID 只在一次运行内稳定，跨方法比较应按物理路径内容匹配。

搜索计数 `terminal_paths`、`omitted_paths` 和 `negative_paths` 是实际评估或支配后保留的候选计数，不是理论完整路径域的基数。比较报告中的完整路径数量必须来自独立全枚举基准。

验证入口为 `cpp/tests/pricing_probe.cpp`、`benders_reference.py`、`formulation_reference.py` 和 `cg_reference.py`；分别检查隐式定价与枚举、固定设计/跨设计割、公共矩阵以及 TSL 同设计全列对照。
