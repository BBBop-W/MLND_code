# 任务级独立指派与骑手送达时限迁移

当前源码直接采用新的任务指派语义，没有保留“首单捆绑/独立任务”并行模型开关。整合在此前其他 agent 的加速实现上完成；修改前的 157 项源码及构建指纹与其验证记录逐项相符。初始工作区含大量未提交改动，因此本次迁移以 `outputs/task_assignment_migration_20261105/BEFORE.json` 和 `before/` 为比较基准，不能将整个 `git diff HEAD` 当成本次迁移独自产生的代码。

## 模型与数据

每个单订单或有序双订单任务 q 独立选择出发基地 l，执行量为 `ν[q] α[q,l] ρ[l]`。单任务 ID 为 r，双任务 ID 为 `R+r*R+s`；K1 有 R 个任务，K2 保留 R+R² 个稳定 ID。零需求任务的指派固定为零，避免无用对称。物理首段总流量仅是相关任务执行量的派生总和。返回基地、空载调位、基地平衡和订单守恒保持原结构。

送达时限使用 `home_receipt_mean`，含骑手从柜到家的收件时间。`receipt_mean` 仍保留原混合收件均值，`removal_mean` 仍用于原柜内占用计算；不能用混合均值替代骑手时间，也不能把混合移除均值与单一模式收件均值强行比较。

新输入 CSV/2 显式保存 home 系数，CSV/1 只读兼容：混合模式依据冻结的 courier receipt 参数，或 courier removal 参数加 last rider mean 恢复；无法识别时明确拒绝。手工物理测试输入未提供 home 系数时，将其原 receipt 字段解释为骑手收件时间。

需求重构的节约排序、剩余需求概率、同类双单扣减和共同基地筛选规则不改。共同支持只参与任务生成；独立任务执行不再受 sibling 的共同基地闸门约束。由于完整路径域按新时限重建，重构数值可能随之变化。续单窗口的既有判断不改。历史 `first_leg_consistency` 与当前独立任务模型冲突，入口拒绝启用。

## 割、认证与上界

任务收益按单个任务取正部；支持、队列 EPI、signed profile、双基地联合割和三态面割均按任务构造。物理 OD 资源供给仍按 OD 聚合，但每个任务以其订单出现次数贡献 `n[r,q] ν[q] α[q,l]`，同 OD 双单贡献两次。

航线任务上界和遗漏列认证都必须把旧的“先合计同首单任务、再对基地取最大”改为“各任务分别对基地取最大，再求和”。遗漏列服务修正为

\[
\Delta_{\rm service}=\sum_q\nu_q\max_l[-\min\{0,\bar c_{ql}^{\min}\}].
\]

两种定价后端使用相同完整域修正。数值安全边际、未完成扫描回退、原始对偶认证和空载列修正保留。图缓存、运营模型缓存及上界支持库的身份包含 home 系数和任务需求，不能复用旧物理域的证书。

ALNS、组合邻域、种子与支持补齐改为逐任务；缺少某个双任务的路径不禁用其单任务 sibling。上界候选需同时通过逐任务执行等式、物理流量和原目标校验。受限修复与稳定化试探主问题的局部界仍不能进入全局 LB。

输出保存 `assignment_scope="task"`、`task_indexing`、`task_table`、`delivery_time_scope="courier_home"` 和独立任务 CSV；OD 汇总按所有包含该 OD 的任务计算。历史 head 解不会静默解释成新设计。任务率尚未生成时，全骑手 checkpoint 仍可保存，其任务率明确为 null，`task_rates_available=false`；不编造已完成的重构信息。
