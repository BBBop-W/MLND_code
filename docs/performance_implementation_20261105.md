## 2. 执行去重与有效性边界

`PointAssessment` 在一次变量／矩阵／锥遍历中同时维护两套原有数值语义：double 可行性门控与 long-double 残差报告。变量界的绝对报告门槛和相对接受门槛没有合并成一个较宽的标准，运算顺序及原比较表达式保留。`streamlined_recourse` 使原始点日志、恢复检查及最终接受检查共用该结果。

缓存只在同一 CG 迭代和同一矩阵中生效。每次新求解、接受恢复候选或替换修复点都显式使评估失效。独立审查特别发现：恢复循环的局部候选可复用相同栈地址，因此地址相同不能证明点相同；现已在每次恢复求解返回后重置评估。原始物理可行性验证保留。

定价 oracle 自己计算精确域快照，再向同次 recourse 调用提供只读身份。没有允许调用方用自报版本号或普通哈希跳过核验。路径身份逐字段序列化，避免 JSON 文本转换和结构 padding；已有列仍逐字段身份核查，新列才追加身份快照。种子列合并沿用旧键，仅为新增 ID 构造键。因此它仍有随活动列数增长的检查成本，不是常数时间版本系统。

`solution_json()` 直接构造实际字段，去除先生成完整零解再覆盖的过程，以及 head 的一次 JSON 往返。公开稠密数组和稳定 ID 不变。没有把全部候选系统重写为稀疏接口，也没有用“同长度”作为信任外部 JSON 的依据。

支持库新增覆盖全部注册路径的分支倒排索引，与原少量代表路径榜单分开保存。缺失分支补全只访问相应 ID 列表，按原 ID 顺序寻找见证；追加目录增量扩展索引。中断或目录不完整仍保留 `unknown_support` 语义。微型等价例中，同样三个见证从原先访问 103 条路径变为访问 3 条；这是该构造例的访问量，不是整体速度倍率。

## 3. 完整目录定价与候选多样性

当 `paths.complete` 为真时，新后端沿规范的 `for_each_path_coefficient` 接口计算

\[
\bar c_p=c_p+\mu_p-a_p^\top\pi.
\]

RMP 成员、合法额外排除、服务列的有效零上界和遗漏列上界乘子均沿用原语义。空驶列在零需求情况下的诊断行为也保留。不完整目录自动回到原标签算法，不能用已有注册列替代全域认证。

一次扫描同时维护候选堆、服务／空驶最小值和各任务分支的保守极小值。分支流量满足 \(\sum_{p\in P_{rlb}}f_p=\nu_{rb}v_{rl}\)，且 \(v\ge0,\sum_l v_{rl}\le1\)，因此仍使用

\[
\Delta=\sum_r\max_l\sum_b\nu_{rb}(-m_{rlb})
\]

控制遗漏服务列的负贡献，其中 \(m_{rlb}=\min\{0,\min_{p\in P_{rlb}^{\rm omitted}}\bar c_p\}\)，无遗漏列的分支取零。整数设计下仍有 \(v_{rl}=\alpha_{rl}\rho_l\)，未省略共享可用率。候选计算与认证计算分别保持 double 和带保守余量的 long-double 累加及向外舍入；非有限计算拒绝认证。

分支加强有独立截止时间，其超时不必废弃普通修正。总定价截止时间仍覆盖候选选择：如果扫描后选择阶段超时，当前实现保守地返回 incomplete。`branch_seconds` 在目录模式中与普通定价时间重叠，诊断明确标记，不能再次相加。

`diverse_pricing` 在最负的至多 \(4B\) 个候选中，优先选择较少出现的首单／任务分支／返航基地组合，再区分资源支持模式，按约化成本及签名确定性破同。必留最负见证；返回批量最多 \(B\)。它只承诺这个有界候选池内的多样性，不保证覆盖完整目录的每个任务，也不改变全域最小值或修正量。

## 4. 设计证书缓存与跨设计 RHS 复用

设计缓存属于一个 `solve_benders` 调用，其数学输入、初始支持和已有路径负载在调用期间不可变，目录只能追加。不会跨调用、跨实例或跨配置复用。默认最多保存 16 个设计，按最近使用淘汰；缓存包含有效仿射割、对应的运营上下界及稀疏原始点。所有严格非零流量均保留，包括极小值；恢复时新增路径补零。

对设计 \(z\) 维护 \(L_z\le Q(z)\le U_z\)：

- 当前 \(\theta<L_z\) 且超过数值容差时，复用有效割并重求全域 master；割已存在而没有新增时删除该设计缓存，下一次重访回到 CG，避免缓存循环。
- \(\theta\ge U_z\) 时可复用已经验证的可行运营点。
- 区间跨越当前 \(\theta\) 且尚未满足原认证条件时继续 CG。
- 只有曾获得原 `recourse_optimal` 证书、且区间按当前运营成本尺度仍闭合，才复用该状态；不能用很大的查询 \(\theta\) 放宽“最优”的容差。

缓存保存发生在 incumbent cleanup 之前，避免将已经关闭闲置设施的解错误地记到原设计名下。缓存仅复制仿射证书必需字段，不复制全目录乘子数组，避免 `clear()` 后仍保留大缓冲区容量；回归检查对此作出断言。单设计下界不直接更新全局 LB，仍须通过有效割和全域主问题。

`reuse_recourse_rhs` 限定固定任务、非 conditional 的普通整数 recourse。设计变化时同时更新记录矩阵与原生求解器的固定等式 RHS；清空价格中心、控制器、旧点和数值恢复状态，并重新求解及完整认证。若旧求解器处于特殊数值 profile，则重建原生模型以恢复正常参数。输入、支持、列负载或模型选项改变仍冷建；conditional 和 free-design/face 模型不使用这种跨设计复用。

## 5. 自适应策略、反馈与双主问题

自适应定价只调发现过程。低原价格接受率使平滑更接近当前原对偶并缩短完整定价间隔；经完整证书确认有进展时才允许恢复探索。间隔有硬上限，接近预计完整定价所需时间时提前尝试原价格定价。批量根据后续原始正流参与度与 RMP／定价耗时调整，始终不超过配置上限。发现轮仍 `discovery_only=true`，不能产生下界或终止证书。

CG 反馈每批至多 64 条路径，支持库最多保留最近两批，每个分支在原低成本名单外至多增加两个反馈候选。证据来自原对偶回验的负列或已验证原模型点的正流；不同设计的价格只影响排名。域和完整路径身份不符即失效，incumbent 正支持始终保留。反馈不是 ALNS 可行性的证明。

反馈接收时间计入共享 primal 额度，但不重置 45 秒搜索冷却时间；否则连续接收反馈可能推迟真正的搜索窗口。位于已有窗口内部的反馈由窗口整体计费，避免重复扣账。

双主问题保留原全域 master 负责 LB，另复制当前约束，加上

\[
c^\top x+\theta\le LB+\lambda(UB-LB),\qquad\lambda=0.5,
\]

按首单／容量状态距离选择候选，并以小权重设施／航线距离破同。候选经过试探模型及原 master 两套检查，目标恢复为原总成本，试探 best bound 不导出为全局 LB。外层每隔一次全域 master 求解尝试一次，每次默认至多 2 秒、累计目标额度为总时限的 5%；失败或局部不可行回退原候选，违反休眠割则先恢复并重求全域 master。

当前支持 origin 模式任意基地数的 MILP master。原生模型构造是现有接口中的原子操作，无法严格按局部切片抢占；构造耗时全额计入，构造后无剩余时间就不再优化。全局构造 guard 仍生效。
