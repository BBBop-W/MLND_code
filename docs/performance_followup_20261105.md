## 1. 结论与优先级

仍有值得推进的空间。最具体的方向是减少反复遍历和转换，并让已经完成的全域计算同时服务多个目的。上轮实现的零率列消除、head 消元、图缓存、同设计 RMP 延续、组邻域、价格平滑与割池管理是本轮的基线，不再当作新增建议。

|---|---|---|---|
| 第一批 | 合并同一点的残差遍历；一次调用内共享域身份；增量维护活动列身份 | 源码中存在确定的重复计算，不改变数学问题 | 必须保留原数值容差及缓存失效语义；收益取决于其时间占比 |

## 2. 代码层：优先减少确定的重复工作

### 2.1 复用评估结果，不削弱验证

当前一次 `feasibility_diagnostics()` 内部就包含三次矩阵遍历；在首次可行且最优、没有改点或重试的普通 RMP 成功路径上，可以静态数出八次顶层行遍历。这个数字描述控制流，不意味着验证占总时间的八分之一或可以获得八倍加速。[源码：诊断入口](/Users/songtaowang/Documents/MLND_code/cpp/src/benders.cpp:172)、[成功路径](/Users/songtaowang/Documents/MLND_code/cpp/src/benders.cpp:914)。

建议把同一点、同一矩阵版本的评估保存为类型化结果，由可行性门控、恢复逻辑与日志共同读取。现有判定使用不同的变量界容差和求和精度，第一版应在一次遍历中保留两种现有数值语义，不能直接用某个 `passed` 标志代替另一种判断。点、行 RHS、变量界或列集变化必须重新评估。

独立物理验证仍有价值：它检查模型组装之外的错误。可缓存的是“当前域中的这条不可变路径具有这些物理系数”，逐解的流量、需求、资源、机队和成本核验仍要进行。内部点应保留类型化支持，减少 JSON 往返和重新建立变量名字索引。完整说明见代码分报告第 1、4、5 节。

### 2.2 缓存身份检查本身也需要成本控制

同一个持久化 subproblem 调用先为 RMP 状态计算完整域身份，随后图缓存构造器再计算一次。低风险改法是让两个使用者共享本次计算的精确快照。[RMP 身份](/Users/songtaowang/Documents/MLND_code/cpp/src/benders.cpp:773)、[图身份](/Users/songtaowang/Documents/MLND_code/cpp/src/pricing.cpp:105)。

更进一步的常数时间版本检查，需要先建立真正不可变的输入域和只追加的路径注册表。当前公开可修改的数据成员不满足这个前提；仅比较指针、路径数量或普通哈希会失去现有检查覆盖。活动列身份也可只为新增列构造一次，避免每次恢复及归还时重新 `JSON.dump()` 全部路径负载。[列身份检查](/Users/songtaowang/Documents/MLND_code/cpp/src/benders.cpp:87)、[快照归还](/Users/songtaowang/Documents/MLND_code/cpp/src/benders.cpp:1412)。

### 2.3 完整分支索引与类型化候选

已有支持库保存少量代表路径，但关闭资源后出现缺口，仍会从完整目录起点扫描。增加覆盖全部注册路径的 `(首单,出发基地,第二单) → 路径ID` 倒排索引，可以只访问缺失分支。其额外内存为线性数量的 ID，最坏时间仍可能扫描全目录；是否值得，应由缺口发生频率和扫描量判断。[当前补全](/Users/songtaowang/Documents/MLND_code/cpp/src/primal_support.cpp:310)。

内部候选则可以用类型化设计、稀疏支持和评估结果表达，只在候选池接纳、checkpoint 或最终导出时生成兼容的公开 JSON。不能丢弃所有未改善全局 UB 的邻居，因为 ALNS 和设计池仍可能使用它们；也不能用稀疏阈值隐藏微小负流或其他违规值。

## 3. 定价层：完整目录上的联合流式扫描

这一节是根据当前模型和实现提出的项目内推导，尚未实现或测试，不是引用某篇论文所得的性能结论。

### 3.1 为什么现在值得考虑

当前 `preprocessed` 入口为了计算固定任务率和支持，已经完整枚举物理路径。普通隐式需求模式则只构建支持，二者必须区别对待。[main.cpp](/Users/songtaowang/Documents/MLND_code/cpp/src/main.cpp:360)。

尽管前者已有目录，定价仍重建标签，在同桶标签之间做两两后缀比较。这里最后一个后缀决策只有交付柜点；`profile()` 会计算各可行遗漏完成的约化成本，按值返回向量，最多缓存 128 个 profile，之后清空。保留标签又会查找后缀并取得物理路径。最后，启用分支修正时还会独立完整扫描服务目录，计算各 `(首单,出发基地,分支)` 的负约化成本下包络。[后缀与支配](/Users/songtaowang/Documents/MLND_code/cpp/src/pricing.cpp:370)、[分支扫描](/Users/songtaowang/Documents/MLND_code/cpp/src/pricing.cpp:494)。

现有 `fast_pricing` 已复用物理路径并避免部分临时向量，因此不能把“复用路径”再列为新算法。新方向是**改变完整目录模式下的定价遍历方法，并合并两次用途重叠的计算**。

### 3.2 计算对象与完整性

分别对服务与空驶定义合格遗漏列集合：服务列按现有 `service_path_enabled` 过滤，空驶列沿用当前可行目录；二者各自扣除当前 RMP 成员和合法额外排除集合，记为 \(\mathcal P_o^S,\mathcal P_o^E\)，其并集为 \(\mathcal P_o\)。当前空驶 oracle 在总需求为零时仍可能报告零上界列的候选和 minimum；首版保留这一诊断语义，不能把统一零上界删除误称为与旧后端输出一致。用于认证时，额外排除必须对应已经显式承担对偶可行性约束或另有合法修正的列，不能任意删去不想扫描的列。对每条列按同一个 canonical 系数接口计算

\[
\bar c_p=c_p+\mu_p-a_p^\top\pi,
\qquad p\in\mathcal P_o,
\]

其中 \(\mu_p\ge0\) 为调用方提供的遗漏列上界乘子；普通原对偶定价中没有该项时取零。已有接口 `for_each_path_coefficient()` 规定了与建模一致的发射顺序。[formulation.hpp](/Users/songtaowang/Documents/MLND_code/cpp/include/mlnd/formulation.hpp:107)。

一次连续扫描可同时维护：

1. 服务和空驶列各自的负部分最小值；
2. 最多 \(B\) 个候选的有界堆，仅保存路径 ID、类别和约化成本；
3. 分支最小值 \(m_{rlb}=\min(0,\min_{p\in\mathcal P_o\cap\mathcal P_{rlb}}\bar c_p)\)；
4. 扫描完成状态及诊断计数。

在目录确实覆盖该调用的完整物理域、排除语义有效、输入和路径负载一致、扫描未中断的条件下，遍历有限集合直接给出所需极小值。它不需要标签支配来证明未保留列不会更优。现有测试已经有独立目录扫描用于验证标签 oracle，但它仍是测试工具，不能描述为已有生产后端。[pricing_probe.cpp](/Users/songtaowang/Documents/MLND_code/cpp/tests/pricing_probe.cpp:46)。

### 3.3 同时得到已有分支修正

这里限定于当前分支修正支持的 `preprocessed + origin + aggregate` 且没有共同首段一致性的模型。实际分支总流量满足

\[
\sum_{p\in\mathcal P_{rlb}}f_p=\nu_{rb}v_{rl},
\qquad v_{rl}\ge0,\quad\sum_l v_{rl}\le1.
\]

在整数设计下 \(v_{rl}=\alpha_{rl}\rho_l\)，即使基地已选中，也不能把实际流量直接写成 \(\nu_{rb}\)。遗漏列只是全分支的子集，由 \(m_{rlb}\le0\) 可得

\[
\sum_{p\in\mathcal P_o^S}\bar c_p f_p
\ge\sum_{rlb}m_{rlb}\nu_{rb}v_{rl}
\ge-\sum_r\max_l\sum_b\nu_{rb}(-m_{rlb}).
\]

因此遗漏服务列的负贡献可由

\[
\Delta_{\mathrm{branch}}
=\sum_r\max_l\sum_b\nu_{rb}(-m_{rlb})
\]

控制；骑手状态贡献零。该推导也适用于仍满足上述分支等式及 \(\sum_l v_{rl}\le1\) 的分数松弛。这个式子正是当前分支修正使用的结构。新后端的作用是顺便维护同一组极小值，而不是发明另一种未经证明的修正。空驶部分继续使用其单独界。合格域、上界乘子和分支定义必须与现有认证链一致。

尤其要保留现有数值保护：上式 \(m\) 表示数学极小值，认证实现实际使用保守下界 \(m^{\mathrm{safe}}\)。当前候选约化成本用 double，分支修正另用 long double、向下误差余量和最终向上舍入。联合扫描可以在同一系数遍历中维护两套累加器，不能为省一次加法就取消保守修正，或把候选 minima 直接当成 \(m^{\mathrm{safe}}\)。NaN、溢出或数值检查失败必须阻止相应认证；完整枚举本身不是浮点误差证明。平滑价格下得到的结果仍只能发现列，不能因为“全目录扫描”就变成当前原对偶的证书。

### 3.4 复杂度、取舍与验收

记目录规模为 \(N\)，平均非零列系数数为 \(a\)，批量上限为 \(B\)。若排除成员检查和分支定位为常数时间，或排除集合按 ID 线性合并，直接扫描的工作量约为 \(O(Na+N\log B)\)；沿用当前额外排除 `std::set` 时还要计入 \(O(N\log(1+|X|))\)。新增内存包括候选堆、分支极小值数组及排除索引；无需预先复制整个稀疏矩阵。当前标签同桶两两后缀比较最坏包含 \(O(\sum_g n_g^2 H)\) 的比较工作，缓存失效还会重复计算 profile；但廉价筛选和强支配可能大幅减少实际扩展。

因此不建议直接删除标签算法。先增加可选 `catalogue_scan` 后端，并限定完整目录使用；隐式目录保持标签搜索。单次扫描可先使用现有流式系数接口，再判断是否需要额外布局优化。完整 CSR 副本、GPU 和多线程扫描都应在确认扫描耗时及内存收益后再讨论。

正确性比较应检查：K1/K2、压缩开关、零率及极小正率、RMP/额外排除、非零上界乘子、空驶、极端价格、截止中断和不完整目录；比较负部分极小值、保守修正、加列合法性及最终认证结果。保留普通定价完成而分支修正因独立预算未完成时的回退语义，不强制两种认证同时成功。**不要求两种后端返回相同的候选集合或支配计数**：原标签法可以删除被支配的列，直接 top-B 则可能保留它们，CG 轨迹自然不同。

性能验收应同时看定价单轮时间、RMP 时间、CG 总轮数及首次完整认证时间。单轮变快而加入冗余列导致总时间增加，不算成功。

## 4. 分解层：复用结论，并改善下一设计的选择

### 4.1 按设计保存认证区间

对同一固定数学域中的整数设计 \(z\)，可保存

\[
L_z\le Q(z)\le U_z,
\]

其中 \(L_z\) 必须来自有效完整域证书，\(U_z\) 来自验证通过的可行运营解。当前 `integer_designs` 主要用于重复计数，同设计原生模型续算也不等于保存并利用所有历史设计的认证结果。[重复设计处理](/Users/songtaowang/Documents/MLND_code/cpp/src/benders.cpp:3865)。

如果区间尚不能确定停止或排除改进，就仍需续算。若 master 对同一设计低估已知 \(L_z\)，应恢复对应全局有效割，或构造适用于该整数设计域的点界并重求主问题，不能简单跳过后继续循环。单个设计的 \(L_z\) 也不能直接当成全问题 LB。

与之相邻但不同的优化是跨设计 RMP 工作区：当前非 conditional 固定设计通过 `fix_j` 等式 RHS 表达，保留共同矩阵、更新 RHS 并重新优化具有明确的实现入口。前者复用已证结论，后者复用模型对象，应该分别消融。conditional 设计依赖系数、额外 face 行、域变更及数值恢复状态需要专门失效规则。

### 4.2 双主问题：认证与试探分开

全域主问题继续提供认证 LB；另一主问题在有效目标水平或邻近区域内挑选下一整数设计，减少每次远距离跳转及重复访问。试探点进入原 CG 和验证链后才能产生割或 UB。

这是设计空间稳定化，与已实现的对偶价格平滑、primal 组邻域各有不同作用。局部试探主问题的 best bound 不进入全局 LB，且需要全域回退和认真步/试探失败的处理规则。Linderoth–Wright 的作者全文第 3 节研究连续两阶段随机线性规划中的 trust-region 选点与接受规则，可借鉴其思想，但不能省略假设后套用其收敛结论。[作者全文](https://arxiv.org/pdf/math/0106151)。更完整的适用边界及当前代码接入点见 Benders 分报告。

### 4.3 更强的联合状态下包络与 single-tree

对于松弛下界，可研究少量 head 与容量档位共同变化时的状态价值，保留共享 \(\rho\)、柜容量及相关资源，形成状态点的有效下包络。已有 two-head queue hull 不代表已经包含这种多资源联合面。用于构造面的每个值都必须是完整状态问题的可靠下界；受限列可行目标不能充当该值。

single-tree branch-and-Benders-cut 则尝试避免反复启动主问题搜索树。它需要自定义分离、候选回调、工作线程与 subproblem 生命周期，不能把 CPLEX 自动 Benders 当成现有 SOCP+CG 的替换开关；IBM 的 candidate context 文档还明确说明该 context 与自动 Benders 不兼容。[IBM 官方文档（22.1.2）](https://www.ibm.com/docs/en/icos/22.1.2?topic=context-cpx-callbackcontext-candidate)。两个方向都保留为研究储备，先用主问题时间、重复设计次数与 LB 进展确认是否值得承担复杂度。

## 5. 定价与原始搜索的协同

已有多列定价不等于有效的批量选择。可以在原对偶负约化成本门槛内兼顾任务覆盖、基地和资源差异，抑制一批近乎相同的路径，并按“定价时间—RMP 时间—认证进展”调整 batch。模板定价预印本已研究在合格负约化成本集合内按模板协调选择列，但本文的资源多样性规则是独立提案，不移用其 GAP 实验效果。[Marshall 等，2026，正文第 3 节](https://arxiv.org/html/2604.12070v1#S3)。

已有固定平滑权重与固定完整定价间隔也可改为进展驱动，但必须保留原对偶完整认证与回退。Pessoa 等的期刊摘要支持“参数自调整和阶段适应已有研究”这一背景；本次未取得全文，不能据此声称当前 SOCP 已获得同一收敛保证。[Pessoa 等，2018](https://pubsonline.informs.org/doi/abs/10.1287/ijoc.2017.0784)。

CG→ALNS 反馈可以包含正流路径、任务缺口、资源影子价格和已验证的原对偶负列，以形成更有针对性的短名单或共同替换邻域。它不应把对偶幅度当成无条件的因果收益，也不能永久删除低分路径。原始搜索得到的改进 UB 与完整定价带来的 LB 改进，应分别记分和报告。

这一组机制具有相互依赖性，建议依次研究“多样性 batch”“自适应平滑”“反向反馈”，最后才引入复杂预算学习器。2025 年 pricing filtering 与 2026 年 template pricing 的原始资料，以及各论文是全文还是摘要级核验，详见[定价与原始搜索分报告](/Users/songtaowang/Documents/MLND_code/docs/performance_followup_pricing_primal_20261105.md)。

## 6. 建议的验证设计

第一阶段只验证局部等价性：同一点残差结果一致；输入或 payload 改变时缓存失效；输出保持逐字段含义；目录定价与穷举在相同数学域上给出保守证书。上述测试不需要借用正在运行的生产实验。

第二阶段才做固定实例、种子、线程、预算、源码与二进制指纹的成对消融。基线固定为当前已验证版本。分别比较执行去重、目录定价、设计证书缓存、跨设计 RHS 工作区、batch/反馈和主问题稳定化；只有单项结果可解释后才组合。

至少记录以下量：

- 总墙钟与峰值内存；身份、快照、评估、序列化、模型构造、RMP、定价和主问题各阶段时间。
- 各阶段调用数、活动列数、目录扫描数、profile 重算数、重复设计数、缓存命中及失效原因。
- 相同时间点的可行 UB、认证 LB、gap、完整定价完成状态、终止原因与独立验证结果。
- 首次可行解、首次完整认证、达到给定 gap 的时间；未达到时明确记为未达到。

重复试验及配对统计可以检验搜索轨迹变化带来的波动。代码重复工作减少只能支持“降低该项执行开销”，尚不能支持“提高整体收敛速度”；更强的局部证书也必须通过全局 LB 轨迹检验其实际价值。

当前交付的是已核查源码的研究方案。新增方向尚未实现，未测量生产性能；前轮实现与验证事实仍以[实现报告](/Users/songtaowang/Documents/MLND_code/docs/acceleration_implementation_20261105.md)和[验证清单](/Users/songtaowang/Documents/MLND_code/docs/acceleration_20261105.validation.json)为准。
