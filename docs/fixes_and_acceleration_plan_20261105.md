### 1.1 修复后的局部分支

设 incumbent 的受选二元变量为 \(\bar d\)，受选集合 \(B\) 与原实现一致，包括设施、容量及指派变量，不包含后续航线变量。局部修复增加

\[
\sum_{j\in B:\bar d_j=0}d_j+
\sum_{j\in B:\bar d_j=1}(1-d_j)\le k.
\]

修复模型保留原任务等式与资源约束，并补入 incumbent 的全部严格正流路径。其已验证解可以更新 UB；其 best bound 不参与全局 LB。这里的“普通搜索”仅指没有上述半径限制，仍可使用限制列集及其自身的固定决策模式，并非完整原问题的全域求解。

启动时仍执行一次普通受限搜索。此后在冷却时间达到 \(\max\{30,0.2T\}\)、没有待续运营设计、剩余总时间大于 10 秒且共享启发式额度尚有余额时，依次执行“局部、普通、局部、普通”。关闭局部分支开关后，到期窗口均为普通搜索。一个窗口只执行一次受限调用；ALNS 模式继续采用自己的调度。普通搜索内部的固定分配／固定设施／coupled 选择由普通调用次数驱动。

这是对开关语义的修复，不是“局部分支必然比普通搜索更快”的结论。短任务可能在冷却时间前结束，因而实际局部尝试数仍可为零。新字段同时保留请求状态、有效开关、实际尝试数和策略说明，避免将“启用”解释成“已经执行”。实现见 [benders_control.hpp](../cpp/include/mlnd/benders_control.hpp) 与 [benders.cpp](../cpp/src/benders.cpp) 的 `restricted_search`、`scheduled_restricted_radius`。

### 1.2 完整调用计时与版本界限

完整受限调用的计费范围包含列选择、模型构造、求解、候选验证与保留、设计池处理、可行解清理以及相应的截止值和进展更新。异常退出也计入实际耗时，正常显式结束后析构不再重复计费。内部例程返回时刻仍单独记录；它不是纯优化器 CPU 时间。

这使下一次调用的额度判断更准确，但不把验证、清理等不可抢占操作变成严格实时截止机制；单次结束时间仍可能稍晚于分配额度。不能声称修复后整个进程绝不超过用户时限。

修复使此前休眠的开关实际生效，搜索轨迹因而变化。结果新增 `restricted_search_revision="20261105"`。现有 preset 名称未改；修复后重新编译的程序不能直接继承旧冻结 baseline 的数值成绩。正在运行的试验、既有生产二进制和输出目录均未改动。

## 3 进一步加速：先减少问题规模，再改善搜索信息

现有实现已经有多类有效割、完整域标号定价、列池复用、ALNS、自适应算子、精英设计和分段运营求解。因此，“再加启发式”“再加 Pareto”“重复运行现有加强”不是充分具体的新方向。建议以每种方法减少哪部分计算、依赖什么等价性或有效性条件来筛选。

| 顺序 | 研究方向 | 可能减少的工作 | 主要成立条件 |
|---|---|---|---|
| A1 | 删除精确零任务率对应的运营列 | 无效列、定价候选及约束非零项 | 任务率先固定；精确为零；认证与列身份一致 |
| A2 | 消去 aggregate 模式中的中间 head 变量与冗余行 | 建模、SOCP 规模及对偶退化 | 保留空支持约束；映射原始解、对偶和定价公式 |
| B1 | 缓存事件图，恢复同一设计的运营 RMP | 分段重复建图、提取和构模 | 模型身份一致；新一轮重新认证 |
| B2 | 邻域路径按需补齐，使用任务／容量组半径 | 无效修复窗口及过小的战略邻域 | 保留所有任务约束、原解支持和原可行性验证 |
| C1 | 平滑价格发现列，原对偶完整定价认证 | CG 振荡与相似列重复加入 | 稳定化结果不充当认证证书 |
| C2 | 已认证割精确去重，再做活跃割池 | 主问题增长与重复割处理 | 保留全域有效性、必要再激活与完整分离 |
| 后续 | 定价信息反馈至 ALNS、跨模块预算学习 | 候选信息浪费和低收益窗口 | 证书链仍获最低服务量，考虑延迟收益 |
| 长期 | 流式／隐式完整路径域 | 完整目录内存及重复扫描 | 固定任务生成和全部全域 oracle 一并保持精确 |

顺序不是性能排名。A 类先有可证明的等价缩减，B 类改变重复工作和邻域覆盖，C 类依赖瓶颈证据。建议每次只引入一个可识别的改变，避免无法归因。

### 3.1 A1：精确零任务率列的消去

对首单 \(r\)、出发基地 \(l\) 和单／双单分支 \(b\)，当前 aggregate 固定任务模型具有

\[
\sum_{p\in\mathcal P_{rlb}}f_p=\nu_{rb}v_{rl},\qquad f_p\ge0.
\]

若固定任务率 \(\nu_{rb}=0\)，则该分支所有流量都被数学上强制为零。将这些变量从运营模型删除，或在完整路径对象仍保留时不向运营求解器添加，得到与原模型相同的可行投影和目标；逆映射只需补零。由此可以减少 RMP 的无效列和候选扫描。此结论不需要改变预处理得到的任务划分。

两个边界尤其重要。第一，不能在任务预处理之前按最终率筛路径，因为完整目录中的成本和支持参与决定任务率。第二，不能把“小正数”阈值化为零；那会改变模型。认证时需显式采用这些变量的有效上界零，或调整零率分支等式的自由乘子，使其满足被删列的对偶约束且不改变对偶目标与设计割系数。若零率等式也删除，还须建立相应的证书提升映射；不能简单把未扫描变量标成已完整定价。旧解中数值微小正流清零后亦须重新验证。

最小验证应逐一比较正率分支支持、原始目标与解恢复，并检查缩减前后完整域证书的下界方向。先在原目录上使用稳定 ID 与活动掩码，比重排目录更容易隔离错误。潜在收益取决于零率分支在整个路径域中所占的比例；本次没有测量该比例。

### 3.2 A2：中间 head 变量的代数压缩

仅考虑 `preprocessed + origin + aggregate` 且 `first_leg_consistency=false`。令 \(h_j\) 表示初始段的执行总量，\(h_{rl}\) 表示同一首单和出发基地的总量。当前构造含有

\[
h_j=\sum_{p:\,j(p)=j}f_p,\qquad
h_{rl}=\sum_{j\in J_{rl}}h_j,\qquad
h_{rl}=H_rv_{rl},\qquad H_r=\sum_b\nu_{rb}.
\]

对非空支持组，将该组所有分支等式相加即得到最后一式；前两式仅定义中间量。在这些变量没有额外独立约束时，可以保留分支等式，消去 \(h_j,h_{rl}\) 及对应定义行，再按路径流恢复结果。非负性和 \(H_r\le\lambda_r\)、\(v_{rl}\le1\) 也蕴含原来的 head 上界。因此该方案有希望同时保持整数模型与连续松弛的可行投影，而不是仅保持某一个整数最优解。

**空支持例外必须显式处理。** 若 \(J_{rl}=\varnothing\)，当前程序没有为该组建立分支行，此时 `orders` 行独自承担 \(H_rv_{rl}=0\)。无条件删掉它会错误放松模型。压缩实现必须保留此约束，或为每个首单／基地／正率分支都建立允许空左端的任务等式。该约束还可能通过 \(v_{rl}=\rho_l\alpha_{rl}\) 影响共同可用率，不能用“该处没有路径”来忽略。

这个证明不适用于历史 lifted／conditional 模式，也不直接适用于共同首段约束；后者的分支比例实际依赖 group head。代码中 `executed_head_rows`、定价的对偶项、增量加列、解提取和独立验证都需要配套映射。数学等价并不意味着求解器会返回相同对偶向量，也不保证运行时间一定下降。先验证小模型投影、恢复解和有效证书，再评估数值退化是否减少。依据见 [formulation.cpp](../cpp/src/formulation.cpp) 的 `build_formulation`、`path_column` 与 `add_columns`。

### 3.3 B1：同一设计的运营状态持久化

当前已在一次 CG 调用内增量加列，跨调用也复用列集合；新增机会是避免每次恢复同一设计都重建输入事件图、模型和求解器表示。建议按三个层次推进：缓存不随设计变化的事件图；保存同一待续设计的 RMP；最后才研究跨设计的 RHS 更新。

同一设计恢复最容易证明，因为其数学问题不变。跨设计则须同步所有本地与求解器 RHS，重新检验原始点、对偶、路径界和完整域修正。持久对象不意味着持久证书。CPLEX 支持模型修改和重新优化，但官方教程中的 simplex 基复用不能直接证明当前 SOCP 具有同样的热启动收益；首先应验证建图、构模与提取是否被节省。[IBM 官方教程](https://www.ibm.com/docs/en/cofz/12.9.0?topic=tutorial-modifying-re-optimizing)

### 3.4 B2：让联合替换进入可搜索邻域

一个潜在的上界瓶颈是：关闭某柜后，代表路径短名单失去某个正任务分支，即便完整目录存在替代路径，局部块仍可能被放弃。可先针对缺失的“首单—出发基地—分支”按需寻找避开关闭资产的见证，再进入原模型修复。若某出发状态在本次受限列域中不可支持，可令该局部状态退出，同时保留其他基地与骑手服务，不能删除相应任务约束。

再将二元位距离改成组距离：首单从基地 1 迁往基地 2 计为一次状态变化，柜容量换档也计为一次，分别设任务半径与容量半径。这样更直接表达“关闭设施—迁移相关任务—开启替代设施”的联合变更。它是对现有 Local Branching 原则的 MLND 结构扩展；文献并未证明这里的双半径一定更快。[Fischetti–Lodi 原始论文](https://link.springer.com/article/10.1007/s10107-003-0395-5)

这两项改变的是受限可行域的覆盖质量。它们不会直接提供全局 LB；更大的邻域也可能增加修复成本。首先检验能否表达原来被短名单阻挡的合法替换，再在相同修复预算下评价 UB 改善。

### 3.5 C 类与长期方向

**平滑价格发现列。** 用当前对偶与历史中心的凸组合搜索候选列，再按当前原对偶重算约化成本；在认证、闭合或连续无进展时回退到原对偶完整定价。只混合行乘子并不自动得到可行 SOCP 对偶点，所以稳定价格不得直接给出 LB 或 `recourse_optimal`。这种分工借用列生成稳定化思想，不移植 LP 收敛结论。[Pessoa 等，2018](https://pubsonline.informs.org/doi/10.1287/ijoc.2017.0784)

**已认证割池。** 先删除完全重复的有效割，再考虑按新增包络改善和活跃性休眠低价值割。删除有效割只会放松主问题，过去取得的认证 LB 仍可保留；但必须在重复设计、终止检查及必要分离时再激活，否则可能反复访问已排除的候选。近似平行或在采样点较弱不构成全域支配证明。

**跨模块信息与预算。** 当前 ALNS 已有算子奖励；下一层才是用近期有效 UB/LB 改善除以完整调用耗时，比较不同可选模块的机会成本。割的收益通常延迟到主问题重优化，不应将下一次 LB 上升全部归于最后一条割。必须保留主问题和完整运营认证的服务份额。近期有利定价列也可反馈至 ALNS 短名单，但旧约化成本只作排序信息。[Hendel 的自适应邻域研究](https://optimization-online.org/wp-content/uploads/2018/12/6992.pdf)

**流式与隐式路径域。** 固定任务率由完整域最低成本和共同支持产生。先让完整枚举流式归约这些统计，可以减少对象常驻内存，但未必减少枚举时间。进一步用精确 oracle 替代枚举，需要同时改造资源割、支持证明、任务成本界、定价修正和上界支持选择，不能只改 CG 就宣称摆脱完整目录。

不建议直接按 OD 写成独立 multi-cut：固定战略设计后，基地可用率、队列库存、机队、柜容量及基地平衡仍耦合不同任务。只有把共享资源提升到主问题并证明投影等价，或做有认证下界的 Lagrangian 松弛，才具备真正分块的理论基础。

## 4 研究验证顺序

建议先完成 A1/A2 的小模型等价性原型，同时单独评估 B1 的重复构造成本。若 UB 长时间停滞且修复块频繁缺支持，再优先 B2；若同一设计出现长尾 CG 和价格振荡，再研究 C1；只有主问题或割规模成为瓶颈时，才扩展 C2。此处使用的是条件式决策，不是对当前试验瓶颈的诊断。

接受标准应同时包括：固定任务率与原始成本保持一致；输出解可恢复并通过独立验证；完整域认证不降级；相同总预算下比较有效 LB、可行 UB 和达到指定 gap 的时间。应分开记录预处理、建图、建模、优化、定价、验证及主问题时间，防止局部变快却使总过程变慢。更少 CG 轮次、更多负列或更好的单次 UB 都不能独立证明总体加速。

本次仅实现第 1 节的确认问题修复。第 3 节均是候选研究方向，未加入求解器、未选择“最佳参数”，也没有性能提升百分比。更详细的证明义务、失败条件、最小对照和一手来源见：
