# L2 求解流程与资源松弛改进

本轮保持固定广义任务、出发基地分配、路径域和全部运营约束不变。主问题仍为设计二元变量加运营成本 epigraph；运营量留在连续子问题。四个新选项默认关闭，旧版本可重复运行。

## 开关和用途

| 开关 | 改动 | 认证边界 |
|---|---|---|
| `--search-scheduling` | 有界主问题逐步收紧、完整子问题机会保障、按时间触发可行解搜索 | 只改变求解顺序与预算 |
| `--dual-lp-first` | 初始化后固定设计普通 CG 优先尝试 cone-ray LP，失败后保留原其他配置 | 原始 primal/dual gap 和完整定价标准不变 |
| `--fractional-path-support` | 完整路径域的分数支持割；需要 `--path-support-cuts` | 当前规范整数设计及其凸包有效，保持最优性 |
| `--airline-resource-balance` | 外部资源 LP 加入基地流量平衡、空载流和对应成本/开放联系；需要 `--airline-resource-cuts` | 原整数可行设计及其凸包的有效松弛 |

## 求解流程

初始可行解继续采用上一轮 `--primal-polish`。新的调度器在每次整数主问题求解后，根据认证下界是否实质提高记录停滞，后续结构筛查的提前返回不会漏掉这次记录。外层 gap 下降本身不触发零 gap 主问题求解。

当近期候选仍被路径支持筛查拒绝时，主问题用较短切片寻找候选。经过完整子问题认证的设计逐渐增多、认证下界持续停滞时，逐步收紧容差并延长切片；连续完整认证而没有分离进展才允许有界的零 gap 求解。所有全局下界仍来自经检查的求解器 best bound 或有效 LP 界，不使用主问题可行目标替代 best bound。

路径存在性筛查始终先执行。对通过筛查的整数候选，较昂贵资源分离按三个候选一次安排，且共享总时限 12% 的整数阶段预算。连续成本割重启有上限，之后继续评估完整运营子问题。该安排不会绕过必要路径检查；成本割被接受也不表示设计本身不可行。根阶段继续使用自身原有预算。

可行解搜索按墙钟时间触发，间隔为 `max(30 s, 0.2 × total_seconds)`，保留原 20% 总启发式预算。初次固定分配联合优化资产和流量，后续允许释放分配。新可行解只更新上界；受限路径 MIP 的局部 bound 不进入全局下界。

分数支持割先在根阶段分离。反复出现八个不支持完整路径的整数候选后，可用总时限最多 5% 的额外预算刷新整数有效主问题的 LP 松弛，每次最多三秒。返回的每条支持割都检查完整物理路径域；只有重新求解松弛以后才更新其下界。原始连续 recourse 诊断与规范化加强根界分别标记。

## 验证与实验

- `search_schedule_probe.cpp`：小外层 gap 不应导致过早零 gap；停滞记录、渐进收紧和资源重启上限。
- `fractional_path_support_probe.cpp`：分数反例、完整域修复、规范整数枚举、预算与缓存边界。
- `airline_resources_probe.cpp`：新旧资源界、原完整模型跨点检查、L2/L3 平衡、空载开放与全列对偶修复。
- `dual_elimination_probe.cpp`：原对偶证书与跨设计弱对偶回归。
- `search_integration_probe.cpp`：L2 单单/双单集成，与完整路径模型对照。

正式批次为 `outputs/l2_algorithm_optimization_20261027`，三例均为既有 TSL L2 M01/M07/M08。每例比较 baseline（上一轮 primal 改进）、schedule（再开前两个选项）、full（四项全开），共九次。每次 600 秒、单线程、seed 43、目标 gap 1%，最多四并发。历史 CPLEX 结果仅作额外参照。结果、认证、运营输出、源代码和二进制哈希由冻结 runner 保存；最终数值以该目录完成后的报告为准。

## 首轮后修正

首轮冻结版本中，分数支持加行会直接占用一轮根阶段配额；M01 的二十轮因此没有执行根阶段运营子问题。当前版本改为支持行与运营子问题在同一轮处理，和其他资源行采用相同顺序。旧分数点仍能产生有效运营割；新支持行的下界效果只在下次主问题重求后计入。

首轮还发现，改变初始化的对偶顺序会改变短时限内的数值恢复和路径池。M07 原顺序完成初始认证，新顺序在三十秒切片内未完成，留下较差初始解。当前版本因此保留 initial_design 和初始化 neighborhood 的原顺序，在初始化完成后再启用 LP 优先。没有放宽任何可行性或证书容差。

这两个修正单独冻结在 `outputs/l2_algorithm_refinement_20261027`，仅重测三个 full_refined。原九次的二进制、输出和失败/停滞证据保持原样。旧 schedule 的结果属于首轮冻结版本，不视为最新初始化规则下 schedule 的实测结果。
