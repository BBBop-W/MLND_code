# K=1：只指定出发基地的订单分配

本说明对应 `codex/k1-origin-assignment` 分支。改动只作用于一次服务活动配送一单的 K=1 模式。K=2 的基地对分配、连续接单需求重构、兼容矩阵及 `aggregate` / `prefix` 规则保持原定义。

## 1. 分配与路径分别决定什么

以 `r` 表示一个 OD，以 `l`、`m` 分别表示出发和返回基地。原来的分配变量为 `alpha[r,l,m]`；当前 K=1 使用 `alpha[r,l]`。若把 OD 拆写为 `(o,d)`，就是由四下标 `alpha[o,d,l,m]` 改为三下标 `alpha[o,d,l]`。

二元分配只选择一个 OD 的出发基地。服务路径仍完整保留出发基地、取餐柜、收餐柜和返回基地。代码中的物理路径仍可按 `b=(l,m)` 存储；删除分配变量中的 `m` 并不删除路径的终点。

令 `P[r,l,m]` 为从 `l` 出发、服务 OD `r` 后返回 `m` 的可行路径集合，定义

\[
\mathcal P_{rl}=\bigcup_{m:(l,m)\in\mathcal B}\mathcal P_{rlm}.
\]

当前 K=1 允许同一 OD 的不同长期服务流量使用不同的返回基地。每一次活动仍沿一条完整路径执行，不是在途中分叉。

## 2. 需求和设施约束

每个 OD 至多选择一个已开放的出发基地：

\[
\sum_l\alpha_{rl}\le1,\qquad
\alpha_{rl}\le x_l,\qquad
\alpha_{rl}\in\{0,1\}.
\]

`h_r` 是 OD 的需求率，`rho_l` 是出发基地的无人机可用率。实际服务量按出发基地汇总：

\[
\sum_m\sum_{p\in\mathcal P_{rlm}}\psi_p
=h_r\alpha_{rl}\rho_l.
\]

设 `w[r,l]=alpha[r,l]*rho[l]`，且 `0<=rho[l]<=1`，精确二元乘积表达为

\[
0\le w_{rl}\le\rho_l,\quad
w_{rl}\le\alpha_{rl},\quad
w_{rl}\ge\rho_l-(1-\alpha_{rl}).
\]

于是需求行的右端为 `h_r*w[r,l]`。没有为每个返回基地分别计算一份 `h_r*alpha[r,l]*rho[l]`，否则会重复需求。

返回基地的开放由路径使用的航线激活约束保证。路径的最后一段进入 `m`，正流量要求该段航线开放，航线开放又要求端点基地开放。返回基地不再出现在 `alpha[r,l]` 的开放约束里。

## 3. 网络、柜格与路径资源

以下结构继续保留：

- 每个基地的服务及空载出发流量等于返回流量。不同 OD 的服务流可以互相平衡，剩余不平衡通过空载调拨消除。
- 基地可用率、FPM 空闲无人机均值及其锥表达不变。
- 路径时间乘以路径流量计入在途无人机需求，空载调拨同样计入机队与成本。
- 格口占用按实际路径流量与该路径的预约时间累加，容量约束不改变。
- 每条路径仍检查首程骑手同步、顾客配送时限、无人机运行时间上限和允许使用的物理飞行网络。

因此，改变的是“哪些路径共同承接一个分配池的需求”。不是忽略返回过程，也不是取消稳态流量守恒。

## 4. 与原 K=1 模型的关系

给定原模型任意可行解，令

\[
\alpha^{\mathrm{new}}_{rl}=\sum_m\alpha^{\mathrm{old}}_{rlm}.
\]

原模型每个 OD 至多指定一个基地对，因此新变量仍为二元。保留原来的全部路径流量、设施和运营变量，即满足新的汇总需求行及其他约束。故在同一物理输入与完整路径域下，原 K=1 的可行解都能映射到新 K=1。

反方向一般不成立：新模型可以让同一 OD 的正流量分别返回不同基地，而原模型只能为该 OD 指定一个返回基地。因此这是一项放宽，不是下标压缩意义上的等价改写。对最小化问题有

\[
Z^{\star}_{\mathrm{new\ K1}}\le Z^{\star}_{\mathrm{old\ K1}}.
\]

这是最优值关系，不能用两个限时 incumbent 的大小直接证明或否定。新模型是否更快、下界是否更紧，需要在同一预算和求解设置下验证。

K=1 的分配二元数量由 `R*L*L` 降为 `R*L`（若候选基地对不全，则原数量为 `R*|B|`）。物理路径域不因此缩小；跨基地返回与空载调拨仍存在。子问题和加强割中按分配池构造的部分可以相应减少，但完整模型的总行列数需要从实际构模统计读取。

## 5. 算法接口

主问题保留设施、柜档、航线和分配整数变量，以及运营成本的 epigraph。K=1 主问题使用起点分配索引；K=2 使用基地对索引。固定设计后的运营子问题继续为 SOCP，路径依然具有两个物理端点。

实现适配应集中在共同的分配索引、设计约束、需求行和列系数上。完整模型、Benders、连续根节点松弛、定价和独立验证应使用相同映射。路径定价不能因为分配只含出发基地就只枚举同基地返回。

C++ 中三个可选加强项 `--assignment-support-cuts`、`--double-support-cuts`、`--joint-base-cost-cuts` 的现有证书依赖固定返回基地，K=1 会明确拒绝它们。一般解析成本下界在可选返回基地上取最小值；资源 LP 的 K=1 约束不再使用返回分配门控。K=2 的这些规则不变。

旧模型产生的割、对偶乘子、固定设计或初始解不能只改数组形状后直接混入新模型。对于以分配池为条件的割，需要按当前池定义重新构造；对于记录了完整物理路径的列，可以在核对输入和资源系数后按新需求行映射使用。

## 6. 保存、复查与比较

读结果时首先核对 `assignment` 的维度和显式的分配范围记录：当前 K=1 为 `(R,L)`、`assignment_scope="origin"`，K=2 为 `(R,L,L)`、`assignment_scope="base_pair"`。Python 在 `result.json` 和 `manifest.json` 顶层记录该字段，原生解也携带范围标识。

Python 独立运营验证与 `export_operations` 支持历史 K=1 三维解，按原来的基地对语义计算，并在运营摘要与 OD 分配表中标识 `base_pair`。历史解的可行性不表示它已在新模型下优化。

新固定设计和 warm start 严格要求当前模型的分配维度，旧 K=1 三维设计会被明确拒绝，接口不自动转换。数学上可对返回基地求和得到起点分配，但如需将其用于求解，应先显式转换并核对当前输入 ID、整数性、唯一分配及设施开放，再重新优化运营流。转换设计不等于原样复用其运营解或下界。

模型或算法比较至少记录：输入哈希、源码版本、K、分配范围、`flow_policy`、完整/隐式路径域、终止原因、可行性检查、incumbent、认证下界、gap、时间、主/子问题规模。K=1 起点分配与 K=2 基地对分配的比较同时包含服务模式和分配域差异。

结果读取、独立核验和绘图的复用入口见 [根 README](../README.md#报告与绘图优先复用已有入口)。新的数值结论应放入对应实验的报告，不写进本文件冒充模型性质。

## 7. 本次实现验证（2026-10-24）

本次代码修改已通过 473 项 Python 测试。C++ 起点分配探针检查了同一 OD 向两个返回基地分流，并核验需求守恒、残差和不适用基地对加强项的显式拒绝；条件需求表达、OD 航线割、结构加强及 K=1/K=2 一般加强探针也已通过。

在现有 2L/20H/50OD 标准实例上，K=1 分配二元和可用率乘积变量分别由 200 个减为 100 个；完整模型由 4064 个变量、4889 条线性约束减为 3864 个变量、4189 条线性约束。2 个锥、1101 条服务路径和 2 条空载路径均保留。

固定同一 K=1 设计后，CPLEX 全路径、CPLEX 列生成、CPLEX 条件子问题和 Gurobi 全路径目标值均约为 9969.26514，最大差异为 0.0000318，全部通过独立运营验证。列生成完整定价通过，认证相对间隙约为 `6.2e-8`。

K=2 回归分两层检查。L01 的完整模型及两种固定设计模式，旧新版本的变量、约束、锥、目标系数和固定值逐项完全相同；L01/L02 使用相同历史设计求解，旧新固定设计 SOCP 的目标、上下界、路径数和模型规模一致，四个结果均通过独立验证。

另在 2L/20H/50OD 上进行了 60 秒上限的 K=1 运行检查：CPLEX 全路径与 Gurobi 全路径分别在约 7.82 秒、1.56 秒达到设定的 0.5% gap；CPLEX Benders 在 60 秒结束时 UB=9973.45002、LB=9752.39465、gap=2.2164%。这些运行用于验证接口和可行性，不构成降维提速结论；达到设定 gap 也不表示零间隙全局最优。
